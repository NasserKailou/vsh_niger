2. APPLICATION MOBILE

Le dossier :

vsh_mobile/

doit contenir une application Flutter moderne.

L'application mobile doit être conçue selon une architecture :

Offline-First.

C'est une exigence fondamentale.

Après la première initialisation et synchronisation :

    l'application doit pouvoir fonctionner sans connexion Internet ;

    les utilisateurs doivent pouvoir consulter les données disponibles localement ;

    les professionnels doivent pouvoir enregistrer certaines opérations hors connexion ;

    les données créées/modifiées hors connexion doivent être placées dans une file de synchronisation ;

    lorsque Internet revient, l'application doit automatiquement synchroniser les données ;

    la synchronisation doit être robuste ;

    aucune donnée ne doit être perdue en cas de coupure Internet ;

    les conflits de synchronisation doivent être détectés et gérés ;

    chaque opération synchronisée doit pouvoir être tracée.

Prévoir notamment :

Local Database
      ↓
Offline Operations Queue
      ↓
Synchronization Engine
      ↓
REST API
      ↓
MySQL

Utiliser une base locale adaptée à Flutter.

Tu dois choisir la technologie la plus pertinente entre SQLite/Drift/Isar/Hive ou autre solution adaptée, puis justifier ce choix.

    Ne crée jamais une fonctionnalité médicale avec une logique clinique arbitraire.

    Ne hardcode jamais les prix.

    Ne hardcode jamais les utilisateurs.

    Ne hardcode jamais les permissions.

    Prévoir les traductions si l'application doit devenir multilingue.
